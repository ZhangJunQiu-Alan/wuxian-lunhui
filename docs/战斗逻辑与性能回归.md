# 战斗逻辑与性能回归

2026-10-18：修复代码审核发现的 5 个问题，并优化技能空间查询和托尔静电场。

## 行为修复

| 问题 | 修复后的行为 |
| --- | --- |
| 通关后选卡恢复战斗 | 战斗分为进行中、结算中、已结束。最终 Boss 击败后立即冻结战斗、关闭奖励和暂停菜单，再等待 3 秒显示结算；死亡和放弃沿用相同的结束保护。过期选卡、重抽、暂停菜单和重复结算回调不能恢复战斗 |
| 雪鞋冷却收益反向 | 射箭步距使用 `150 × 冷却倍率`，保留移动余量；一次跨过多个步距时补齐射箭。没有目标时最多保留一次待射距离 |
| 完整无敌仍受持续伤害 | 巴德尔的完整无敌和刺客护盾均阻挡持续伤害；普通受击无敌仍不会阻挡持续伤害 |
| 对尸体重复发丰收奖励 | 弗雷攻击入口排除死亡、已排队删除和失效的目标，避免同帧后续攻击重复发经验或苹果 |
| 包围事件突破敌人上限 | 普通刷新、精英、包围事件、Boss 召唤的小怪和延迟分裂统一经过生成入口检查数量；达到关卡 `max_enemies` 后不再生成普通敌人 |

### 敌人上限的例外

Boss 本体、加姆的 4 根锁桩，以及支线必需目标允许超出常规敌人上限，以免任务无法完成。支线例外包括冰块、锚链、指甲堆、祭司、冰海来客与索克；它们的普通护卫和分裂产物仍受上限限制。

`spawn_enemy(..., required = true)` 只用于上述必要目标。任何生成路径在本局进入结算后都返回空值，调用方已处理这种情况。

敌人死亡或被支线移除时，立即退出可攻击组和空间索引，不必等到帧末释放节点。

## 空间查询优化

- 圆形、线段、范围伤害、神术索敌和持续区域共用敌人空间网格。
- 移动、生成、死亡、离开场景、Boss 潜地和重新出现时同步更新索引；查询覆盖目标自身半径。
- 查询覆盖的网格过多时回退到索引中的敌人列表，避免大范围技能枚举大量空格。
- 持续区域同一次更新的伤害与拉拽共用目标列表。
- 静电场通过网格查找附近感电敌人，使用平方距离，先确定邻居数量再结算伤害；觉醒连锁也使用空间查询，并遵守 40 个目标的既定上限。

### 局部 CPU 微基准

固定随机种子，350 只敌人；以下为同一轮无窗口测试的数据。

| 场景 | 参考实现 | 优化后 | 耗时降低 |
| --- | ---: | ---: | ---: |
| 2,000 次小范围圆形查询 | 逐个遍历 222.725 ms | 网格 27.439 ms | 约 87.7% |
| 30 次静电场结算 | 原两两遍历 1,262.750 ms | 网格 288.001 ms | 约 77.2% |

圆形查询参考实现使用逐个遍历的距离判定；静电场参考实现取自审核基线 `7b6ab98:scripts/gods/thor.gd`。回归脚本的可选参数 `--static-baseline=<参考脚本路径>` 可额外运行静电场前后对照。

这些结果只说明给定分布下的局部 CPU 成本，不代表整局帧率。该轮检查使用当时的 30 级上限；2026-10-19 已按下节更新为 40 级。尚未进行完整 10 分钟试玩、图形渲染性能测试或玩家手感验收。
