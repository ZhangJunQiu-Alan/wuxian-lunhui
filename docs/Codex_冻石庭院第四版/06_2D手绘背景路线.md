# 06 · 路线切换：2D 手绘背景（哈迪斯做法）

**2026-11-18 制作人决定**：场景美术停用「Python 脚本建模 + AI 贴图 + 纸片树」路线，改为《哈迪斯》式 2D 手绘背景。原因：脚本拼出来的门、墙和石碑做不出雕刻质感，由明度推算的法线让材质发糊，树是贴纸，整体"一看就是 AI 做的"。

本文件覆盖 03、04 中与建模相关的要求。README 的硬性规则（Git、Godot 测试参数、存档保护）继续有效。

## 画面组成

固定的正交斜俯视镜头不变（当前约 49°，`CAMERA_OFFSET` 方向不变），所以一张按这个投影画好的图，在游戏里看起来就是对的。

| 层 | 内容 | 实现方式 |
| --- | --- | --- |
| 地面背景 | 角色能站上去的一切：石板、雪地、路沿、墙根积雪、崖边、崖下冰海 | 一张或几张高分辨率手绘图，按镜头投影贴到地面上，镜头平移时与地面严格对齐 |
| 前景遮挡层 | 会挡住角色的物体：墙、门柱、长厅木架、近处的树 | 从背景里切出来的带透明通道的图层，按世界坐标立在正确深度上，角色走到后面时被正确遮挡（沿用已有的遮挡剪影） |
| 动态精灵 | 出口门两种状态、入口木闸、火盆火焰、传送光幕、符文发光 | 单独绘制的精灵或序列帧，加上现有的 shader 和粒子 |
| 光效 | 火光、传送门照亮地面 | 叠加模式的光晕精灵，不靠实时光照 |
| 碰撞 | 墙、悬崖、门 | 沿用现有碰撞锚点和不可见的 3D 白盒，**白盒不渲染** |

角色（2D 像素精灵）、战斗逻辑、房间流程完全不变。

## 制作流程：白盒渲染 → 手绘覆盖 → 切层

1. **白盒引导图**：用现有的 v4 场景几何（只看布局，不看质量），按游戏镜头的投影渲染整个房间的高分辨率引导图，至少是游戏内 1 像素 = 引导图 2 像素。同时导出：只有地面的图、每组遮挡物的遮罩、深度图。这一步保证手绘图和碰撞位置完全对齐。
2. **手绘覆盖**：以引导图为构图基础，以目标图 A1、B1、C1 为风格参考，生成手绘风格的成图。
   - 房间超出一张图时分块生成，块与块之间留重叠，最后统一调色、消除接缝。
   - 全房间用同一个光照方向（左上方低角度暖光，冷蓝阴影）、同一套色板、同样的笔触密度。
3. **切层**：用第 1 步的遮罩，把遮挡物从成图里切成独立图层，并补画被遮挡物挡住的地面。
4. **接入 Godot**：把地面层和遮挡层放进现有舞台，替换 v4 的网格和材质，隐藏白盒，保留碰撞。

### Blender 在这条路线里的用途

按 README「电脑操作」的要求，在 Blender 界面里手工建模，不再用脚本拼几何体：

- **白盒和构图**：在界面里调整布局、比例和镜头，渲染引导图、遮罩和深度。
- **关键物件**（出口门、入口木闸、符文石碑）：在界面里认真建模和雕刻，带上交织纹、兽首这些大中形体，再用游戏镜头渲染成底稿，作为手绘覆盖的结构基础。模型的形体越准确，手绘出来就越不容易"结构融化"。
- 渲染底稿也可以直接作为精灵使用，前提是它在实机里和手绘背景的风格统一。

## 质量红线（防止"AI 味"）

逐张检查，出现以下任何一项都要返工，或者局部重画：

- 光照方向前后不一致，或者阴影方向乱
- 结构融化、穿插：柱子融进墙里、木梁凭空消失、门框不对称地变形
- 符文是乱码。必须使用真实的古弗萨克符文（Elder Futhark）字形，同一扇门上的符文保持一致
- 细节噪声过量：到处都是同样密度的碎纹，没有大中小层次，中央战斗区不干净
- 块与块之间有接缝，或者色调跳变
- 树、石头大量复制同一个形状
- 与碰撞不对齐：角色能走进画出来的墙里，或者被看不见的东西挡住
