# 美术与音频素材规范

分工：Codex 制作素材，Claude 审核、接入游戏并实测，用户验收。风格见[游戏整体美术风格](游戏整体美术风格.md)，技术路线见[技术细节](技术细节.md)。

2026-11-19 起不再做像素素材：场景是手绘背景，角色是实时 3D，界面按古典碑刻方向重新设计。`assets/sprites/` 里的像素图是旧版，换掉之前代码还在用，不要删。

距离和尺寸用「身位」：1 身位 = 角色身高。

## 一、场景：手绘背景

固定的正交斜俯视镜头下，每个房间由这几层组成：

| 层 | 内容 | 要求 |
| --- | --- | --- |
| 地面底图 | 整个房间的地面、路、积雪、冰面，一张或几张手绘大图拼成 | 和镜头角度严格对齐；角色走得到的地方不能画会被误认成障碍的东西 |
| 前景遮挡层 | 建筑、立柱、树、掩体等会挡住角色的部分，单独成层，带深度图 | 角色走到后面时被挡住，并显示剪影 |
| 动态精灵 | 门、火盆、光门、旗帜、粒子 | 底部要和地面衔接：积雪、碎石、接触阴影和投影，不能是一条直线切在地上 |
| 3D 白盒 | 构图参考和碰撞 | 不出现在画面里 |

- 每个房间先出目标概念图，用户选定后再按镜头出引导图、重绘和拆层。
- 原稿、引导图、提示词和制作记录放 `assets/source/<关卡>_<房间>/`，运行时资源放 `assets/models/<关卡>/<房间>/`。冻石庭院是样板：`assets/source/midgard_courtyard/v5_painted/`。
- 每处改动都要进游戏截图核对，五个以上同类物件（火盆、石碑）要逐个看。

## 二、角色：实时 3D

样板是[剑士 3D 试点](Codex_剑士3D试点/README.md)。每个角色按这个流程做，每一步都停下来让用户验收：

1. **风格方向**：两三种绘画语言的立绘，加一张画进实机截图的样张，用户选定。
2. **设定定稿**：三视图（正、侧、背，A-pose）、单张正面图、武器、头像、游戏内渲染目标图。三视图画得干净，给建模用，不带笔触。
3. **基础模型**：图片生成 3D 工具出模型，在 Blender 里修整。约 2–5 万三角面，脚底在原点，身高统一，武器是独立物体（可以换武器）。
4. **骨骼和动作**：待机、跑步、冲刺、攻击连段、受击、死亡，大招另做。
5. **接入**：风格化着色器、替换游戏里的角色、实机截图和录像。

- 四个角色不要求同一种画风，按出身换笔触，共用同一套光照和色板。不要明显玩具感的卡通 3D，不要全身粗黑描边。
- 游戏里角色约 1.5 个世界单位高。
- 防具不显示在角色身上，只有图标。武器显示在手上。
- 敌人和 Boss 也走 3D 路线，等剑士试点跑通再定具体规格。

## 三、特效

- 在 3D 场景里用粒子、网格和着色器做，范围按身位标，和判定范围一致。
- 敌人的危险区用红橙色。玩家自己的技能和地面图标不要大面积用红橙，避免和危险区混淆。
- 刀光等武器特效和角色身体分开做。

## 四、界面与图标

- 方向是「古典碑刻 + 深蓝星图 + 精细金属装饰」（[游戏整体美术风格](游戏整体美术风格.md)第八章）。先出界面样张给用户选，再定图标尺寸和画法。
- 图标是手绘，不是像素。
- **稀有度不画进素材**：同一件装备会以任意稀有度出现，颜色由代码加在名字、图标底框和光效上。

## 五、音频

- 音效 `assets/audio/sfx/<名字>.wav`，单声道、44.1 kHz、16 位；音乐 `assets/audio/music/<名字>.ogg`。按名字播放，放 `<名字>_01`~`_03` 时随机挑一个。代码在 `scripts/core/audio.gd`。
- 新音效的响度对齐现有的 `pickup_xp`、`heal_pickup`。

## 六、交付规则

1. 开工前先核对已有素材和实际加载代码，已有合格的不重做，不覆盖旧文件。
2. 每批放在 `assets/source/<批次>_<日期>/` 或对应房间、角色的目录：说明、原稿、候选、定稿、预览、记录（真实提示词、参考、退稿原因）。
3. 在游戏实际画面里检查（原速、慢放），不以图库代替游戏画面。没运行、没试听的不标通过。
4. 新来源先确认可商用，记进 `assets/LICENSES.md`：文件、来源、作者、授权、链接。需要登录、付费或授权不清时先问用户。免费生成工具出的模型如果是 CC BY 4.0，按要求署名。
5. 人物只按史实、神话和本项目设定画，不参考其他作品的角色。
6. AI 生成已获用户允许（2026-10-16）。Steam 商店页要披露 AI 生成内容。
7. 要用户验收或挑选的产出，做成本地的验收网站，用户处理完就删掉网站，结论写进对应的说明或制作记录。
