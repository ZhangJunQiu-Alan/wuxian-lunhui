## 实际工具与制作

使用用户已批准的 OpenAI 内置图像工具。每条新动作输入对应项目自有静态图，提示词只写外观，不含人物名或其他作品名。Pillow仅处理最近邻尺寸、二值透明、统一静态RGB色板、裁排、整帧定位、透明边缘碎片和预览，没有在Python重画Boss。

巨船展帆状态实际在 Chrome 的 Piskel 修正：将两状态按640×320分帧导入，展帆颜色先映射到收帆版48色；用矩形选择、复制、清除、粘贴，将顶部、下方船身和左右两端从收帆版固定到展帆版，只保留中央帆布变化。工程 originals/naglfar_states_repaired.piskel、导出 originals/naglfar_states_piskel_export.png、截图 previews/piskel_ship_repair.png。导出是640×640的两帧纵排，最终仅裁出第二帧，不对角色或船体重画。四个固定矩形与收帆版逐像素一致，见 generation_naglfar_sail_v03.json。Chrome中途断线后重连，备用应用内编辑没有产出，不计为修图工具。

## 实际自检

每项 records/reviews.json 记录可见特征与失败原因。看过 #121721 深底下的实际1×和最近邻4×，检查所有动作相位、角色比例/装具/左右生死分半、固定脚底或地下遮挡基线、首尾衔接、程序特效不混入角色。毒池与裂纹按其非正方形/正方形特效尺寸单独检查。

技术核对包括精确尺寸、PNG RGBA、alpha仅0/255、每格至少2px留白、不超过48色，同一Boss所有动作RGB取自静态图色板。每条动画有4倍8fps GIF，游戏攻击建议16fps。GIF用120/130ms交替；3相位动画在GIF中放两个循环，共6个GIF帧以使平均帧率准确达到8fps，PNG仍只有3格。final_audit.json逐像素核对每个GIF相位与PNG，并核对正式、approved、候选哈希。循环变化量仅作辅助，不能替代目视检查。
